# ESP GIS Server

#### Note that if you are looking for the previous node version, it is archived [here](https://github.com/locatrix/esp-gis-server/tree/node).

ESP GIS Server is a free, standalone web server written for the .NET Framework. It takes GeoPackages generated by Locatrix and serves them up through standard WMTS/WFS endpoints, and also offers a browser-based viewer.

This allows you to consume ESP GIS GeoPackages in a self-hosted way, without any dependencies on Locatrix web services. This approach is recommended for emergency services applications.

### Requirements
*   .NET Framework 4.8
*   Windows 10 or later
*   IIS (for production hosting)

## Getting Started

This project is designed to be run from Visual Studio or hosted in a Windows IIS environment.

### Running locally using Visual Studio

1.  Clone this repository to your local machine.
2.  Install [Node.js](https://nodejs.org/) (which includes npm) and then install Yarn globally by running:
    ```bash
    npm install --global yarn
    ```
3.  Open the `EspGisViewer.sln` file in Visual Studio (2019 or newer is recommended).
4.  Configure the path to your GeoPackages by editing the `web.config` file at the root of the `EspGisViewer` project. Find the `<appSettings>` section and update the `EspGeopackagesPath` value:
    ```xml
    <appSettings>
      <!-- Path to the Geopackages directory -->
      <add key="EspGeopackagesPath" value="C:\path\to\your\geopackages" />
      ...
    </appSettings>
    ```
5. `[Optional]` To use the ESP Web Viewer, you will need to configure a [mapbox](https://www.mapbox.com/) access token. See the `EspGisViewer/Client/README.md` for the configuration details.
6.  Press `F5` or the "Run" button in Visual Studio. This will automatically:
    *   Install client-side dependencies using Yarn.
    *   Build the client-side viewer application.
    *   Build the .NET server application.
    *   Start the server using IIS Express and launch the viewer in your default web browser.

Once the server is running, the following URLs can be used (the port will be assigned by Visual Studio):

| Resource | URL |
|---|---|
| Web Viewer | `http://localhost:[PORT]/viewer` |
| WFS Endpoint | `http://localhost:[PORT]/wfs` |
| WMTS Endpoint | `http://localhost:[PORT]/wmts/capabilities.xml` |

### Running in Production

For production use, it is recommended to deploy the `EspGisViewer` project to a dedicated Internet Information Services (IIS) server. IP-based restrictions can be applied in IIS to ensure that only authorized traffic is able to access the server.

#### Scaling
ESP GIS Viewer is designed to scale horizontally. Because the server only requires read-only access to the GeoPackage data, you can scale the server across multiple nodes without any additional configuration.

## Server Data Sources

The ESP GIS Server reads GeoPackage data from a folder on the filesystem.

By targeting a folder rather than individual GeoPackage files, ESP GIS Viewer is able to automatically show data from the most recent packages without any config updates or server restarts.

GeoPackages must be named using the following convention, where filenames may start with anything but must end in a standard suffix:

| Package | Name |
|---|---|
| Tiles | `***-tiles-YYYYMMDD.gpkg` |
| Features | `***-features-YYYYMMDD.gpkg` |

This naming convention is followed by Locatrix when pushing new GeoPackages to your storage location, so you typically won't need to worry about anything.

ESP GIS Viewer checks for newer GeoPackages on requests to capabilities URLs, and up to every 5 minutes when accessing tile/feature URLs. The server will always use data from GeoPackages with the newest timestamp in their filename.

## Configuration

Configuration is managed through the `web.config` file in the `EspGisViewer` project.

### `filesystem` Data Source
Point the server to a folder on your filesystem that contains the GeoPackages by setting the value associated with the `EspGeopackagesPath` key.

```xml
<appSettings>
  <add key="EspGeopackagesPath" value="C:\path\to\your\geopackages" />
</appSettings>
```

### Configuring access tokens
By default, the server does not enforce authentication and expects that network-level security (like an IP whitelist in IIS) is used. This is because the WFS and WMTS protocols do not directly support modern security features.

You can add a second layer of security by requiring that an access token is provided in the URL. This is configured by setting the `EspAuthenticationToken` in `web.config`:

```xml
<appSettings>
  <add key="EspAuthenticationToken" value="your-secret-token" />
</appSettings>
```

You can also use the environment variables `ESP_GIS_ACCESS_TOKEN_1` and `ESP_GIS_ACCESS_TOKEN_2` to support zero-downtime token rotation.

If access tokens are configured, the server's endpoints change to include the token:

| Resource | URL |
|---|---|
| Web Viewer | `http://localhost:[PORT]/ACCESS_TOKEN/viewer` |
| WFS Endpoint | `http://localhost:[PORT]/ACCESS_TOKEN/wfs` |
| WMTS Endpoint | `http://localhost:[PORT]/ACCESS_TOKEN/wmts/capabilities.xml` |

## Caveats

*   ESP GIS Viewer only works with GeoPackages created by Locatrix - it does not work with standard GeoPackages. This is because the server relies on the special data structure and indices contained in Locatrix-generated GeoPackages to enable efficient querying.
*   The WMTS/WFS implementations in ESP GIS Viewer are extremely minimal and do not yet conform to 100% of the standards. They have been tested to work under:
    *   ArcGIS Online (Map Viewer Classic)
    *   ArcGIS Online (Map Viewer)
    *   QGIS
